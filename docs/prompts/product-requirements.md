# 바이브코딩용 최종 프롬프트

나는 **일상 가계부, 공동 정산, 여행 지출 관리를 하나의 플랫폼에서 제공하는 통합 가계부 앱**을 개발하려고 한다.

이 앱의 핵심 문제의식은 다음과 같다.

기존에는 일상 가계부는 일반 가계부 앱, 친구와의 정산은 Splitwise나 카카오톡/토스 정산, 여행 경비는 여행 가계부 앱을 따로 사용해야 한다. 하지만 실제 사용자의 관점에서는 일상 지출, 여행 지출, 친구들과 함께 쓴 돈이 모두 **같은 기간 안에서 발생한 나의 지출**이다.

특히 공유 지출에서는 카드/현금에서 빠져나간 **결제액**과, 정산 후 내가 실제로 부담해야 하는 **실제 소비액**이 다르다. 이 앱은 이 둘을 명확히 분리해서 보여주고, 공유 지출과 여행 지출이 개인 월간 가계부에 자연스럽게 반영되도록 만드는 것을 목표로 한다.

앱의 한 줄 컨셉은 다음과 같다.

> **혼자 쓴 돈과 같이 쓴 돈을 한 달 가계부에서 함께 보고, 여행 지출은 환율/정산/AI 분석까지 지원하는 통합 가계부 앱**
> 

중요한 제품 철학은 다음과 같다.

> **일상은 가볍게, 공유는 정확하게, 여행은 똑똑하게.**
> 

---

## 1. 앱의 핵심 방향

이 앱은 단순 여행 가계부가 아니다.

또 단순 공동 정산 앱도 아니다.

기본은 **일상 가계부**이고, 여기에 **공유 지출 정산 기능**과 **여행 지출 분석 기능**이 포함된다.

앱의 주요 지출 유형은 다음과 같다.

### 1) 개인 지출

혼자 사용한 지출이다.

예시:

- 식비
- 카페
- 교통
- 쇼핑
- 구독
- 고정비
- 생활비

개인 지출은 일반 가계부처럼 빠르게 입력되어야 한다.

이 앱에서 일상 가계부의 비중이 가장 크기 때문에, 개인 지출 입력은 매우 직관적이고 가벼워야 한다.

가장 중요한 UX 원칙:

> **기본 지출 입력은 5초 안에 끝나야 한다.**
> 

기본 입력 화면에는 최소한의 필드만 보여준다.

```
금액
카테고리
메모
저장
```

공유 지출, 여행 연결, 통화 변경, 영수증 첨부 같은 기능은 기본 화면에서 숨겨두고, 사용자가 필요할 때만 펼칠 수 있게 한다.

---

### 2) 단발성 공유 지출

친구, 연인, 모임, 계모임 등에서 한 번 발생하는 공유 지출이다.

예시:

- 친구들과 식사
- 카페 모임
- 택시비
- 계모임 회식
- 생일파티
- 단체 주문
- 모임비

이 경우 중요한 것은 **누가 결제했는지**와 **각자 실제로 얼마를 부담해야 하는지**를 분리하는 것이다.

예를 들어 사용자가 4명이 먹은 식사비 80,000원을 카드로 결제했다면:

```
카드 결제액: 80,000원
내 실제 부담액: 20,000원
받을 돈: 60,000원
```

반대로 다른 사람이 결제했다면:

```
내 카드 결제액: 0원
내 실제 부담액: 20,000원
보낼 돈: 20,000원
```

공유 지출은 정산 결과가 개인 가계부에 자동으로 반영되어야 한다.

---

### 3) 여행 지출

여행은 혼자 갈 수도 있고, 여러 명이 함께 갈 수도 있다.

따라서 여행 기능은 **공유 여부와 독립적으로 동작**해야 한다.

여행 지출은 다음을 지원한다.

- 혼자 여행
- 친구/연인/가족과 함께 가는 여행
- 국내 여행
- 해외 여행
- 현지 통화 지출
- 원화 지출
- 카드 결제
- 현금 결제
- 환전 기록
- 여행 예산 관리
- 여행 후 AI 리포트

여행 기능의 핵심은 단순 기록이 아니라, 사용자의 여행 소비 패턴을 분석해서 다음 여행 예상 비용과 카테고리별 예산을 추천하는 것이다.

## 2. 가장 중요한 차별점: 결제 기준과 실제 부담 기준 분리

이 앱에서 가장 중요한 개념은 **결제액**과 **실제 소비액**을 분리하는 것이다.

### 결제 기준

내 카드/현금/계좌에서 실제로 빠져나간 금액이다.

예시:

```
내가 친구 4명 식사비 80,000원을 결제함
→ 결제 기준 지출: 80,000원
```

### 실제 부담 기준

정산을 반영한 뒤, 내가 실제로 부담해야 하는 금액이다.

예시:

```
4명이 균등 분할
→ 내 실제 부담액: 20,000원
```

월간 가계부에서는 사용자가 두 기준을 모두 볼 수 있어야 한다.

예시:

```
6월 소비 요약

카드/현금 결제액: 1,320,000원
정산 받을 돈: 240,000원
정산 보낼 돈: 0원
실제 소비액: 1,080,000원
```

이 기능은 공유 지출이 많은 사용자에게 중요하다.

카드값은 커 보이지만 실제 소비는 더 낮을 수 있기 때문이다.

또한 소득공제, 카드 사용액, 월별 결제 흐름을 확인하려면 결제 기준 금액도 필요하다.

따라서 결제 기준과 실제 부담 기준은 둘 다 제공되어야 한다.

## 3. 앱의 핵심 가치

기존 앱들의 문제:

```
일상 가계부 앱
→ 공유 정산 기능이 약함

Splitwise 같은 공동 정산 앱
→ 개인 월간 가계부와 연결되지 않음
→ 한국어 지원이 약함

여행 가계부 앱
→ 여행 지출은 잘 보이지만, 한 달 전체 소비와 분리됨
```

이 앱의 해결 방식:

```
일상 지출
+ 단발성 공유 지출
+ 여행 지출
+ 정산 결과
+ 실제 부담액
+ 여행 AI 분석

= 하나의 월간 가계부에서 통합 관리
```

앱의 포지션:

> **가계부 따로, 정산 앱 따로, 여행 가계부 따로 쓰는 문제를 해결하는 앱**
>

Splitwise의 주요 기능을 참고하되, 한국 사용자에게 맞게 더 직관적으로 구현한다.

- 멤버 초대
- 지출 등록
- 결제자 선택
- 참여자 선택
- 균등 분할
- 직접 금액 입력
- 비율 분할
- 특정 멤버 제외
- 받을 돈/보낼 돈 계산
- 정산 완료 처리
- 부분 정산
- 다중 통화 지출
- 여행/모임별 그룹 정산

차별화할 부분:

```

5. 여행 기록 기반 AI 예산 추천
6. 여행 끝에 남은 현지 현금까지 정산에 활용
```

## 6. 홈 / 월간 요약 화면

홈은 일상 가계부 중심이어야 한다.

사용자는 앱을 열자마자 이번 달 돈의 흐름을 이해할 수 있어야 한다.

필수 표시 항목:

- 이번 달 결제액
- 이번 달 실제 소비액
- 받을 돈
- 보낼 돈
- 정산 완료 금액
- 정산 미완료 금액
- 이번 달 예산 대비 사용률
- 정산 반영 후 남은 예산
- 카테고리별 실제 소비
- 최근 지출 목록
- 빠른 지출 입력 버튼

예시 UI:

```
6월 소비 요약

결제 기준: 1,320,000원
실제 부담 기준: 1,080,000원

받을 돈: 240,000원
보낼 돈: 0원

정산 반영 후 남은 예산: 420,000원
```

홈 화면에는 결제 기준/실제 부담 기준을 전환할 수 있는 토글이 있어야 한다.


## 11. 해외여행 환율/현금 기능

해외여행에서는 카드 결제, 현금 결제, 원화 결제, 현지 통화 결제가 섞일 수 있다.

따라서 여행 지출에서는 환율 기준을 기록할 수 있어야 한다.

### 지출 기록 시 통화 처리

기본 UX:

```
현지 통화 입력
→ 원화 자동 환산
```

고급 옵션:

```
결제 통화 선택
- 현지 통화로 기록
- 원화로 기록
- 현금 지갑에서 차감
```

### 환율 기준

다음 환율 기준을 지원한다.

```
TRAVEL_DEFAULT
- 여행 생성 시 설정한 대표 환율

EXCHANGE_RECORD
- 사용자가 실제 환전한 환율

MANUAL
- 사용자가 직접 입력한 환율

SETTLEMENT_DATE
- 정산 시점 환율
```

## 12. 여행 현금 지갑 기능

해외여행에서 사용자는 현지 현금을 환전해서 가져갈 수 있다.

따라서 여행별로 현금 지갑을 만들 수 있어야 한다.

예시:

```
일본 여행 현금 지갑

환전:
500,000원 → 50,000엔
적용 환율: 10.0원/엔

지출:
라멘 1,200엔
편의점 800엔

남은 현금:
48,000엔
```

현금 지출은 해당 현금 지갑에서 차감된다.

현금 지갑은 여행 종료 후 정산에도 사용할 수 있다.

## 13. 혼합 통화 정산 기능

여행 정산에서 중요한 차별점이다.

여행이 끝났을 때, 현지 돈이 남을 수도 있고 남지 않을 수도 있다.

일행과 정산할 때 일부는 현지 현금으로 주고, 나머지는 원화 계좌이체로 정산할 수 있어야 한다.

이 기능은 단순 부분 정산이 아니라 **혼합 통화 정산**이다.

예시:

```
B가 A에게 갚아야 할 돈: 80,000원

1차 정산:
B → A: 3,000엔 현금 지급
적용 환율: 9.2원/엔
원화 환산: 27,600원

남은 정산금:
80,000원 - 27,600원 = 52,400원

2차 정산:
B → A: 52,400원 계좌이체
```

지원해야 하는 정산 방식:

```
1. 전액 원화 정산
2. 전액 현지 통화 정산
3. 일부 현지 통화 + 일부 원화 정산
4. 일부만 정산
5. 여러 번 나눠 정산
```

UX 예시:

```
지수님이 민지님에게 받을 돈
80,000원

[전액 정산 완료] [일부 정산]
```

일부 정산 클릭 후:

```
정산 방식 선택

1. 원화 계좌이체
2. 현지 현금으로 정산
3. 현지 현금 + 원화로 나눠 정산
```

혼합 정산 선택 후:

```
받을 돈: 80,000원

현지 현금으로 받은 금액
3,000엔

적용 환율
10.0원/엔 [변경]

원화 환산 금액
30,000원

남은 정산금
50,000원

[남은 금액 원화 정산 완료 처리]
```

이 기능의 목적:

> **여행 끝에 남은 현지 돈까지 정산에 반영할 수 있게 한다.**
> 

사용자용 문구:

> 남은 엔화로 일부 정산하고, 나머지는 원화로 정산하세요.
>

## 14. 여행 AI 리포트 기능

AI는 전체 가계부에 무리하게 붙이지 않는다.

AI는 **여행 지출 분석과 다음 여행 예산 추천**에 집중한다.

단발성 공유 지출에는 AI를 붙일 필요가 없다.

단발성 공유 지출은 빠른 정산이 핵심이다.

여행은 다음 데이터가 있기 때문에 AI 분석 가치가 있다.

- 여행 기간
- 여행 지역
- 국내/해외 여부
- 혼자/동행 여부
- 고정비
- 현지 지출
- 카테고리별 지출
- 날짜별 지출
- 환율
- 실제 부담액
- 정산 후 최종 소비액

### AI 리포트 제공 내용

- 이번 여행 총평
- 결제액과 실제 부담액 차이 분석
- 카테고리별 지출 분석
- 날짜별 지출 속도 분석
- 여행 초반/후반 과소비 패턴
- 예산 초과 원인 분석
- 과거 유사 여행과 비교
- 다음 여행 예상 비용 추천
- 다음 여행 카테고리별 예산 추천
- 소비 성향 태그

### AI 리포트 예시 1: 월간 소비 해석

```
이번 달 카드 결제액은 132만 원이지만,
공유 지출 정산 예정 금액 24만 원을 제외하면
실제 소비액은 108만 원입니다.

이번 달 지출이 커 보이는 이유는
여행 숙소비와 모임 식사비를 사용자가 먼저 결제했기 때문입니다.
```

### AI 리포트 예시 2: 다음 여행 예산 추천

```
지난 2번의 3박4일 여행에서
사용자의 실제 부담액은 평균 62만 원이었습니다.

다음 3박4일 여행에서는
숙박/항공 제외 개인 현지 지출 예산을 38만 원 이상으로 잡는 것이 적절합니다.

특히 식비와 카페 지출은 여행 후반부에 증가하는 경향이 있습니다.
```

### AI 태그 예시

- 식비 집중형 여행자
- 카페 지출 증가형
- 쇼핑 변동형
- 고정비 선결제형
- 여행 후반 과소비형
- 교통비 과소예산형
- 현지 지출 예산 부족형
- 정산 후 실제 소비 안정형

## 15. AI 분석 로직 방향

처음부터 LLM이 모든 판단을 하게 하지 않는다.

데이터 기반 계산과 규칙 기반 분석을 먼저 수행한 뒤, LLM은 자연어 리포트 생성에 사용한다.

분석 흐름:

```
여행 지출 데이터 수집
→ 결제액/실제 부담액 분리
→ 고정비/현지비 분리
→ 여행 기간 기준 하루 평균 지출 계산
→ 카테고리별 지출 비율 계산
→ 날짜별 지출 속도 계산
→ 과거 유사 여행과 비교
→ 예산 초과 패턴 탐지
→ 다음 여행 예상 비용 계산
→ LLM이 자연어 리포트 생성
```

다음 여행 예산 추천 MVP 로직:

```
유사 여행 조건:
- 여행 기간이 비슷함
- 국내/해외 여부가 같음
- 혼자/동행 여부가 같음

추천 현지 지출 예산:
과거 유사 여행의 1일 평균 실제 부담액 × 새 여행 일수

여유 예산:
추천 예산 × 1.15

카테고리별 예산:
과거 유사 여행의 카테고리별 평균 비중 × 추천 예산
```

## 16. 기술 스택 추천

1차 개발은 **모바일 앱 → 웹 연동** 방식으로 간다.

추천 기술 스택:

```
모바일 앱:
React Native + Expo + TypeScript

웹:
Next.js + TypeScript

백엔드:
NestJS + TypeScript

DB:
PostgreSQL + Prisma

로컬 저장소:
Expo SQLite

서버 상태:
TanStack Query

앱 전역 상태:
Zustand

인증:
초기 mock 로그인
이후 Kakao / Apple / Google 로그인

AI:
초기 mock AI report
이후 OpenAI API 또는 AWS Bedrock 연동 가능하도록 서비스 레이어 분리

배포:
앱 - EAS Build
웹 - Vercel
백엔드 - Render / Railway / Fly.io / AWS ECS 중 선택
```

이 스택을 추천하는 이유:

1. 앱과 웹과 백엔드를 모두 TypeScript 중심으로 개발할 수 있다.
2. `Expense`, `ExpenseShare`, `Travel`, `Settlement` 같은 데이터 모델이 중요하므로 타입 통일이 유리하다.
3. React Native + Expo는 iOS/Android 앱을 빠르게 만들 수 있다.
4. Expo는 카메라, 이미지 업로드, 푸시, 딥링크, 공유 기능을 붙이기 쉽다.
5. Next.js는 추후 웹 가계부/대시보드/관리자 화면으로 확장하기 좋다.
6. PostgreSQL + Prisma는 정산/공유/여행 같은 관계형 데이터 모델에 적합하다.
7. Expo SQLite를 사용하면 오프라인 지출 입력 후 서버와 동기화하는 구조를 만들 수 있다.
8. TanStack Query는 서버 데이터 캐싱/동기화에 적합하다.
9. Zustand는 입력 중 임시 상태, 토글, 필터, 사용자 설정 같은 가벼운 전역 상태 관리에 적합하다.

## 17. 다른 기술 옵션

### 옵션 A. React Native + Expo

추천도: 가장 높음

장점:

- 앱 먼저 만들기에 빠름
- iOS/Android 동시 대응
- React 경험을 활용할 수 있음
- 웹은 Next.js로 확장 가능
- TypeScript 공유가 쉬움
- 카메라/푸시/딥링크/공유 기능 구현이 쉬움
- 오프라인 저장소 구현 가능

단점:

- 아주 복잡한 네이티브 기능은 한계가 있을 수 있음
- 앱/웹 UI를 완전히 하나로 공유하기는 어렵다

### 옵션 B. Flutter

추천도: 높음, 하지만 2순위

장점:

- 모바일 UI 성능이 좋음
- iOS/Android 일관성이 좋음
- 차트/애니메이션 구현이 깔끔함

단점:

- Dart를 새로 배워야 함
- 웹 확장성은 Next.js보다 불편할 수 있음
- 백엔드와 타입 공유가 어렵다

### 옵션 C. PWA / Next.js 웹앱 먼저

추천도: 낮음

장점:

- 개발이 빠름
- 배포가 쉬움
- 웹 연동이 자연스러움

단점:

- 매일 쓰는 가계부 앱으로는 모바일 UX가 약할 수 있음
- 푸시/카메라/공유/오프라인 동작이 제한적일 수 있음
- 홈 화면 접근성과 앱다운 사용성이 부족할 수 있음

### 옵션 D. Kotlin/Swift 네이티브

추천도: MVP에는 과함

장점:

- 성능과 UX가 가장 좋음
- 위젯/푸시/카메라/로컬 저장소 최적화가 좋음

단점:

- iOS/Android를 각각 개발해야 함
- 개발 속도가 느림
- 혼자 MVP 만들기에는 부담이 큼

## 19. 핵심 계산 로직

반드시 다음 계산을 구현한다.

### 1) 결제액 계산

```
결제액 = 내가 paidBy인 Expense의 amountKRW 합계
```

### 2) 실제 소비액 계산

```
실제 소비액 = 개인 지출 + 공유 지출에서 내 ExpenseShare.shareAmountKRW 합계
```

공유 지출에서 내가 결제자인지는 실제 소비액 계산에 직접적인 기준이 아니다.

내 실제 소비는 내가 부담해야 하는 `ExpenseShare` 기준이다.

### 3) 받을 돈 계산

```
받을 돈 =
내가 결제했지만 다른 사람이 부담해야 하는 금액 중
아직 정산되지 않은 금액
```

### 4) 보낼 돈 계산

```
보낼 돈 =
다른 사람이 결제했고 내가 부담해야 하는 금액 중
아직 정산되지 않은 금액
```

### 5) 여행 실제 부담액

```
여행 실제 부담액 =
해당 Travel에 연결된 ExpenseShare 중 내 userId의 shareAmountKRW 합계
```

### 6) 여행 결제액

```
여행 결제액 =
해당 Travel에 연결된 Expense 중 paidBy가 나인 amountKRW 합계
```

### 7) 현금 지갑 잔액

```
현금 지갑 잔액 =
초기 환전 금액 - 현금 지출 - 현금 정산 지급액
```

### 8) 혼합 통화 정산 차감

```
정산 차감액 KRW =
paidAmount × exchangeRateToKRW
```

```
남은 정산금 =
기존 remainingAmountKRW - convertedAmountKRW
```

남은 정산금이 0 이하가 되면 Settlement 상태를 DONE으로 변경한다.

0보다 크면 PARTIAL 상태로 둔다.

## 22. UI / UX 원칙

이 앱에서 가장 중요한 것은 사용자가 기록에 피로를 느끼지 않도록 하는 것이다.

UX 원칙:

```
1. 일상 지출 입력은 5초 안에 끝나야 한다.
2. 기본 입력 화면은 단순해야 한다.
3. 공유/여행/환율 기능은 필요할 때만 펼친다.
4. 숫자는 크게 보여준다.
5. 결제액과 실제 부담액 차이를 직관적으로 보여준다.
6. 정산 상태는 한눈에 보여야 한다.
7. 여행 화면에서는 남은 예산과 하루 사용 가능 금액을 강조한다.
8. AI 리포트는 긴 분석표보다 자연어 요약 + 근거 수치 조합으로 보여준다.
9. 앱은 가볍고 빠르게 동작해야 한다.
10. 한국 사용자 기준으로 용어를 자연스럽게 사용한다.
```

추천 디자인 스타일:

- 토스처럼 숫자가 잘 보이는 카드형 UI
- 편한가계부처럼 빠른 기록 중심
- Splitwise처럼 정산 흐름이 명확한 구조
- 여행 화면은 예산/환율/현금 잔액이 잘 보이게 구성

# 짧은 버전 프롬프트

아래는 처음 방향 잡을 때 쓰는 짧은 버전이다.

```
개인 지출, 공유 지출, 여행 지출을 한 플랫폼에서 관리하는 통합 가계부 앱을 만들고 싶다.

핵심은 결제 기준 금액과 실제 부담 기준 금액을 분리해서 보여주는 것이다. 예를 들어 내가 4명 식사비 80,000원을 결제했다면 카드 결제액은 80,000원이지만 실제 부담액은 20,000원이고, 나머지 60,000원은 받을 돈으로 표시되어야 한다.

이 앱은 기본적으로 일상 가계부가 중심이다. 따라서 지출 입력은 매우 직관적이고 가벼워야 하며, 사용자가 기록에 피로를 느끼지 않도록 기본 입력은 금액/카테고리/메모/저장 정도로 5초 안에 끝나야 한다. 공유 지출, 여행 연결, 통화 변경, 영수증 첨부는 고급 옵션으로 숨겨둔다.

앱은 개인 가계부, 단발성 공유 지출 정산, 여행 지출 관리를 제공한다. 여행은 혼자 갈 수도 있고 여러 명이 갈 수도 있다. 단발성 공유 지출에는 AI를 붙이지 않고, 빠른 정산과 개인 가계부 자동 반영에 집중한다. 여행 지출에는 AI 분석을 붙여서 과거 여행 기록 기반으로 다음 여행 예상 비용과 카테고리별 예산을 추천한다.

Splitwise의 그룹 정산, 결제자/참여자 분리, 균등 분할, 직접 금액 입력, 부분 정산, 다중 통화 기능을 참고하되, 한국어 중심 UX와 개인 월간 가계부 자동 반영으로 차별화한다.

해외여행에서는 현지 통화, 원화 결제, 카드 결제, 현금 결제가 섞이므로 환율 기록이 필요하다. 여행별 현금 지갑을 만들 수 있어야 하며, 사용자가 실제로 환전한 환율을 기록하고 현금 지출 시 해당 지갑에서 차감한다.

중요한 차별 기능으로 혼합 통화 정산을 지원한다. 예를 들어 B가 A에게 80,000원을 갚아야 하는데 여행 끝에 3,000엔이 남았다면, 3,000엔을 현금으로 일부 정산하고 적용 환율로 원화 환산한 뒤, 남은 금액만 원화 계좌이체로 정산할 수 있어야 한다. 이때 SettlementPayment를 따로 저장해서 어떤 통화와 어떤 수단으로 얼마를 정산했는지 기록한다.

MVP로 다음을 구현해줘.

1. 월간 홈 화면
- 결제 기준 소비액
- 실제 부담 기준 소비액
- 받을 돈
- 보낼 돈
- 정산 상태
- 카테고리별 실제 소비
- 최근 지출

2. 지출 등록
- 개인 지출
- 공유 지출
- 결제자와 실제 부담자 분리
- 균등 분할/직접 금액 입력
- ExpenseShare 자동 생성

3. 공유 지출
- 단발성 모임/계모임/택시/식사 정산
- 부분 정산
- 정산 상태 관리
- 개인 가계부 자동 반영

4. 여행
- 여행 생성
- 여행 기간/지역/통화/예산
- 혼자 여행/공동 여행 모두 지원
- 여행 지출 등록
- 여행별 실제 부담액/결제액/남은 예산 계산
- 현금 지갑
- 환전 기록
- 현지 통화/원화 환산

5. 혼합 통화 정산
- 일부 현지 현금 정산
- 나머지 원화 정산
- 적용 환율 기록
- 현금 지갑 잔액 차감
- 남은 정산금 계산

6. AI 여행 리포트
- 이번 여행 결제액과 실제 부담액 차이 분석
- 카테고리별 지출 분석
- 과거 비슷한 여행 기반 다음 여행 예산 추천
- 카테고리별 추천 예산
- 자연어 리포트 생성은 mock 함수로 우선 구현

기술 스택은 앱 우선 개발을 위해 React Native + Expo + TypeScript를 사용하고, 웹은 Next.js, 백엔드는 NestJS, DB는 PostgreSQL + Prisma를 사용한다. 로컬 저장소는 Expo SQLite, 서버 상태 관리는 TanStack Query, 앱 상태 관리는 Zustand를 사용한다.

실제 실행 가능한 MVP 코드, 폴더 구조, DB 스키마, API 목록, 더미 데이터, README까지 작성해줘.
```
